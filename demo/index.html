A real QR code, drawn as a living maze.

People wander the corridors, a monster hunts them, a forest grows round it by day and a city by night, and it is built to stay readable while it moves. Type anything and scan.

Docs

One script, one function. No server, no CDN, no build step.

  1. 1. Copy two filesvendor/qrcode-generator.min.js and src/maze-qr.js from the repo.
  2. 2. Add the scriptsPlain <script> tags, before your own code.
  3. 3. DrawrenderArtisticQr(text, size) returns a live canvas.

On a web page

<div id="qr"></div>
<script src="vendor/qrcode-generator.min.js"></script>
<script src="src/maze-qr.js"></script>
<script>
  var canvas = renderArtisticQr("https://example.com/", 1000);
  canvas.style.width = "100%";
  document.getElementById("qr").appendChild(canvas);
</script>

Day and night

Leave night out and the maze follows <html data-theme="dark">, cross-fading when it changes:

document.documentElement.setAttribute("data-theme", "dark");   // the maze turns to night by itself

A still image (PNG)

var still = renderArtisticQr("https://example.com/", 1200, {still: true, night: false});
var png = still.toDataURL("image/png");

The "copied" reaction

navigator.clipboard.writeText(url).then(function () { mazeCheer(url); });

renderArtisticQr(text, size, options)

Returns a <canvas> of size × size pixels, or null if the text is too long for a QR code.

OptionDefaultWhat it does
nightfollows the pagetrue / false fixes the theme; leave it out to follow data-theme.
stillfalseDraw one frame and stop.
motionfalseAnimate even when the system asks for reduced motion.
fps30Frame rate of the animation.

Other functions

mazeCheer(text)Plays the reaction: people jump, cars crash or pirates fight.
canvas.__stop() / __start()Pause and resume the animation.
verifyCores(canvas)Checks that every module's centre is within its bit's tone: {bad, worst}.
MAZEAll tunables: error correction, quiet zone, colours, people count, speeds…

The bits come from qrcode-generator; the drawing never decides them. The art is a skin over a valid code:

  • Dark modules become hedges, light ones become paths, so the maze is the code.
  • Finder, timing, alignment, format and version modules are drawn whole and high-contrast; nothing walks over them.
  • Safe cores: after every frame, the centre of each module the animation touched is clamped back to its bit's tone (dark ≤ 0.16, light ≥ 0.91 luminance). A figure crossing a module shows as a tint, never a flipped bit.
  • The quiet zone stays clear; the scenery begins beyond it.

Every push is tested with three decoders (ZXing, ZBar, quirc) on plain, degraded and camera-like images, and the crowd's behaviour is simulated for regressions.

  • Size. The art needs about 12 screen pixels per module. Smaller, it simplifies; below 5 it falls back to a plain code. Longer text makes a bigger code, which needs a bigger canvas.
  • Screens first. For print, export a still PNG at high resolution and test it with a phone before printing.
  • Always dark on light. Even at night the code keeps dark modules on light paths: inverted codes read badly on many phones.
  • CPU. A live canvas redraws at 30 fps. Lower fps, call __stop() when it is off screen, or use still for many codes on one page.
  • Decoders differ. On the test set ZXing reads 99.3%; on the harshest test images ZBar and quirc drop to about 89–93%. These are synthetic distortions, not a field test with phone cameras.
